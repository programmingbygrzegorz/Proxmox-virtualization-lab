# 10. Wysoka dostępność (HA)

HA w Proxmoxie automatycznie uruchamia VM na innym węźle, gdy jej węzeł padnie.

## Warunki – bez nich HA nie zadziała

1. **Quorum po awarii jednego węzła.** W klastrze 2-węzłowym wymaga to [QDevice](03-klaster.md#qdevice--trzeci-głos-dla-klastra-2-węzłowego). Bez niego węzeł, który przeżył, nie ma quorum i nie uruchomi niczego.
2. **Dyski na storage współdzielonym** (`grzegorz-pool`) – VM 110 i 111 trzeba najpierw przenieść z `local-lvm`.
3. **Storage współdzielony musi przetrwać awarię** – przy Ceph `size 2 / min_size 2` awaria hosta wstrzymuje zapisy, więc VM wystartuje, ale zawiśnie na I/O. W labie do testów HA ustaw tymczasowo `min_size 1` (i przywróć potem 2).
4. Sprawny **fencing** – Proxmox używa watchdoga (`softdog` domyślnie): węzeł bez quorum sam się restartuje po ~60 s, dopiero potem VM startuje gdzie indziej. Dzięki temu ta sama VM nigdy nie działa na dwóch węzłach naraz.

## Konfiguracja

### GUI

1. (PVE 8) *Datacenter → HA → Groups → Create*: `grupa-pve`, węzły `pve:2,pve2:1` (wyższy priorytet = preferowany węzeł).
   (PVE 9) grupy zastąpiono **regułami HA** (*Datacenter → HA → Rules*): reguła *node affinity* określa preferowane węzły; istniejące grupy są migrowane automatycznie.
2. *Datacenter → HA → Resources → Add*: VM 130, *Max. Restart* 1, *Max. Relocate* 1, *Request State* `started`.

### CLI

```bash
ha-manager add vm:130 --state started --max_restart 1 --max_relocate 1
ha-manager status
ha-manager config
```

## Test awarii (ćwiczenie)

1. `ha-manager status` – VM 130 `started` na `pve2`.
2. Odłącz kabel sieciowy `pve2` (albo `systemctl stop pve-ha-lrm corosync` – mniej realistyczne).
3. Obserwuj na `pve`:
   ```bash
   watch -n2 'pvecm status | grep -E "Quorate|Total"; ha-manager status'
   ```
4. Oczekiwane: po ~1–2 min `pve2` → `fence`, VM 130 → `started` na `pve`.
5. Podłącz kabel – `pve2` wraca do klastra, VM zostaje na `pve` (chyba że reguła/grupa ma `nofailback 0` i `pve2` jest preferowany).
6. Zapisz czasy w [ćwiczeniach](cwiczenia.md).

## Tryb serwisowy węzła (planowane prace)

```bash
ha-manager crm-command node-maintenance enable pve2    # zasoby HA migrują na pozostałe węzły
# aktualizacja, restart...
ha-manager crm-command node-maintenance disable pve2
```

Ustawienie *Datacenter → Options → HA Settings → shutdown_policy = migrate* sprawia, że przy zwykłym `reboot` VM HA same się przenoszą.

## Replikacja ZFS (alternatywa bez Ceph)

Gdy węzły mają lokalny ZFS zamiast Ceph, *Replication* kopiuje dyski VM co kilka minut na drugi węzeł. HA działa wtedy z utratą danych z ostatnich minut. Nie dotyczy LVM-thin.
